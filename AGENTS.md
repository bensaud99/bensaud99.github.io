# bensaud99.github.io — APT source + Pages site

Static GitHub Pages repo: the site (`index.html`, `js/data.js`) and the APT
source (`debs/` indexed by `.github/workflows/*`). Installable packages live in
`debs/` named `<Package>_<Version>_<Architecture>.deb`; `Packages`, `Release`
and `_site/` are generated by CI and are gitignored — never commit them.

Everything marked `iphoneos-arm64e` targets the roothide bootstrap (Dopamine
RootHide). The device this repo is maintained on is iOS 16.4.1 roothide.

This repository is the one place packages are published from: a new tool, tweak
or update is built, committed to `debs/`, listed in `js/data.js` and pushed
here — not to a second repository and not uploaded elsewhere.

## Working on this repo
- `shell_run` runs as `mobile`; its `/` is the jbroot, so real paths appear
  under `/rootfs/...`.
- `git_*` tools only. Never force-push.
- There is no Apelin build description here: packages are built by hand as
  below and committed as binaries.

## One publisher, one source name
`.github/workflows/update-repository.yml` is the only workflow that publishes
Pages: it runs `scripts/update-repository.sh`, which indexes `debs/` and copies
the site into `_site/`, then deploys that with `actions/deploy-pages`. A second
workflow (`repo-builder.yml`) used to push to a `gh-pages` branch on every
push; it was removed because it deployed a differently labelled `Release` and
whichever workflow finished last decided the source's name in Irisin/Sileo.

The name clients show comes from `Origin`/`Label` in `Release`, and
`Release` is generated, never committed. Both are set in
`scripts/update-repository.sh` to `سورس بن سعود | Ben Saud Repo`; change the
name there, not in the workflow. Its trigger paths mean an edit to the script
or to `debs/`, `depictions/`, `index.html` republishes the source — a change
that merely deletes another workflow does not.

## The site: only files and links that exist
`index.html`, `css/style.css`, `js/data.js` and `js/main.js` are the whole site;
images live in `assets/` (SVG artwork drawn by hand, no remote stock photos) and
in `depictions/<package>/`. Nothing on the page may point at a file that is not
in the repo or at a URL nobody owns: a card whose package is not published yet
carries `soon: true` in `js/data.js` and renders a disabled
`.is-unavailable` label instead of a download button, and the headline count
(`#stat-published`) is computed from the cards that really have a
`downloadUrl`/`trollstoreUrl`.

`scripts/update-repository.sh` copies **everything** into `_site/` except the
repository's own machinery (`.git`, `.github`, `scripts`, `debs`, `Attachments`,
`Packages*`, `Release`, `_site`, the markdown files). It used to copy a
whitelist and shipped a page whose `css/`, `js/` and `assets/` were all 404 —
if you change what the site needs, change the exclusion list, never a whitelist.
The workflow's `paths:` must list every directory the site uses (`css/**`,
`js/**`, `assets/**`, `index.html`, `sileo-featured.json`, …) or a push that
only touches them deploys nothing.

## Rebuilding CopyLog Arabic (`com.bensaud.copylogarabic`)
The Arabic localization of the CopyLog tweak (upstream: TomT000). The packaged
payload is copied from the upstream deb; only `DEBIAN/postinst` and the
`Version` field are ours.

Source tree kept on the device outside the repo:
`/var/mobile/Documents/copylog-ar4/` — a full `dpkg-deb -R` extraction of the
package with our edited `DEBIAN/control` and `DEBIAN/postinst`.

```sh
cd /var/mobile/Documents
dpkg-deb --root-owner-group -Zzstd --build copylog-ar4 \
  com.bensaud.copylogarabic_<version>_iphoneos-arm64e.deb
cp com.bensaud.copylogarabic_<version>_iphoneos-arm64e.deb \
  <repo>/debs/
```

`--root-owner-group` is required: building as `mobile` would otherwise ship
`mobile:mobile` files. `-Zzstd` matches the upstream payload compression.
Do not use `fakeroot` on this device — its `chown` interposition does not work.

Then bump `version` and `downloadUrl` for `id: 5` in `js/data.js`, delete the
previous deb from `debs/`, commit and push.

### Why the postinst writes `/var/lib/dpkg/info/me.tomt000.copylog.list`
The upstream preference bundle (`Library/PreferenceBundles/CopyLog.bundle`)
checks `fileExistsAtPath:` on `/var/lib/dpkg/info/me.tomt000.copylog.list` and
`/var/jb/var/lib/dpkg/info/me.tomt000.copylog.list`. The Arabic package
`Conflicts: me.tomt000.copylog`, so that file never exists and the bundle shows
its "this copy was not installed from a repo" lock page instead of the
settings. Our `postinst` creates an empty marker file (root:wheel, 0644) in
whichever dpkg info directory exists, so the pane works for every user with no
manual step.

### Testing a new build on the device
```sh
# as root: forget the marker, install the deb locally, confirm it is rebuilt
rm -f /var/lib/dpkg/info/me.tomt000.copylog.list
irisin-cli install --yes /private/var/mobile/Documents/<package>.deb
ls -l /var/lib/dpkg/info/me.tomt000.copylog.list      # recreated by postinst
icli app kill --force com.apple.Preferences
icli url open 'prefs:root=CopyLog'                    # then read the screen tree
```
The Arabic settings pane must appear (تفعيل، لصق تلقائي، …) rather than the
lock/"paywall" page.
